# Step 2: V3 from the XLS schedule

**Shows:** a stage-level TLM view (V3) generated from the XLS schedule of A0
is cycle-exact against the A0 RTL, runs faster, and its cost does not grow
with the number of instances; the system bench gives the first
blocks-per-clock number.

```bash
dfm run vectors-run-v3  > logs/v3.log 2>&1        # TEST PASSED, "v3 clks per op: 4"
dfm run vectors-run-fid > logs/fid.log 2>&1       # "fid ops=32 rtl clks=128 v3 clks=128"
dfm run bench-v3-run    > logs/bench-v3.log 2>&1  # "view=v3 blocks=8 clks=128"
dfm run vectors-run-speed-rtl > logs/speed-rtl.log 2>&1   # "ops=400000 clks=1600000"
dfm run vectors-run-speed-v3  > logs/speed-v3.log 2>&1    # same counts; ~1.4 s vs ~3.8 s
dfm run scale-run-v3-n64k1    > logs/s.log 2>&1           # "N=64 K=1 ops=40000 clks=159999"
```

`scale-run-rtl-n64k1` and `-n1k1` are the RTL counterparts (RTL walltime
grows from 0.45 s at N=1 to 33 s at N=64; V3 stays ~0.18 s).

**Results:** {doc}`../design/baseline`, sections "System bench per view",
"Cycle fidelity V3 vs A0 RTL", "Sim speed V3 vs RTL" and "Scaling bench".
